# Final Project — Fall 2026, DS 325

## Overview

Semester-long **team project**. Group size: **2–3 people** (no solo projects).
Each member must contribute throughout the process.

## Repository Requirements

- Codebase (and optionally documents) must live in a **GitHub or GitLab repo**.
- At **every checkpoint** (except the Abstract report), **every team member must have at least one commit** in the repo for that checkpoint.
  - Members without a commit record for a checkpoint are considered non-participating and receive only **60%** of the team's grade for that checkpoint.
- All code should be written in **Python** (Jupyter Notebook or `.py` files both valid).
- The repo's code must **run** and reproduce the outputs described in the report/presentation.

## Project Substance

### Usefulness
The project must be useful — not modeling for modeling's sake. It should have real application and potential users.
- Example: predicting when/where crimes may occur in urban areas (real application, real potential users).

### Main Point
The project needs either:
- **A thesis** — an argument to support (e.g., "providing services for children — school lunch, daycare, etc. — predicts higher standardized test scores"), **or**
- **A design goal** — a predictive/descriptive tool to build (e.g., "a tool to help sports bettors pick winners by identifying the most important team statistics for predicting game outcomes").

### Complexity
Must have sufficient complexity for a full semester of work. Complexity can come from (examples, not exhaustive):
- Collecting and curating your own dataset.
- A research question with multiple layered/related sub-questions requiring different models.
- Model complexity: many inputs from different data sources, tackling a complex problem space, or custom model construction/training methods.
- Other justified sources of complexity.

**Not sufficient:** taking one Kaggle dataset, picking 4 features to predict 1 target, and using an existing/pre-packaged method. That level only meets mini-project requirements.

### Data Requirements
- Must be **real data**, not synthetic.
  - Caution with Kaggle: lots of synthetic/ML-designed datasets there. Real data usually has descriptive attributes — an author/source and documentation of how it was collected.
- **At least 300 samples.** If under 2,000 samples, must justify the sample size.
- Must **cite the data source** and describe how the data was collected.
  - If the team collects/curates its own data, document the collection process in detail and include the dataset in the project output.
- Data must be accessible to the instructor by the **end of the semester**.
